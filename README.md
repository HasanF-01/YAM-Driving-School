تطبيق اختبارات السوق النظري (نسخة مبنية على نفس فكرة تطبيق `drivingschooltest.github.io/amal`
مع شعار وألوان YAM).

| الملف | الوصف |

(المصدر: `TAKE_COUNT` و `PASS_MARK` في `serve.js`، ونسخة مطابقة في `exam-client.js`
يفرض `scripts/static-check.js` بقاءها متطابقة).

## وضعان للتشغيل

`exam-client.js` يجرّب `POST api/exam/start` أول مرّة، ويقرّر الوضع مرّة واحدة لكل جلسة:

| | **وضع الخادم** (`serve.js` / Docker) | **الوضع الساكن** (GitHub Pages) |
|---|---|---|
| من يوزّع الأسئلة | الخادم | المتصفّح |
| من يصحّح | الخادم | المتصفّح |
| بنوك الأسئلة | لا تُنزَّل — طلبها يرجع **403** | تُنزَّل كاملةً **بأجوبتها** |

القواعد واحدة في الوضعين: 30 سؤالاً، النجاح 24، والجواب المؤكَّد أول مرّة لا يتغيّر.

### وضع الخادم — الأجوبة تبقى عنده

كل شيء يمرّ عبر ثلاث نقاط في `serve.js`:

| النقطة | الطلب | الجواب |
|---|---|---|
| `POST /api/exam/start` | `{ bank }` | `examId` + 30 سؤالاً **بدون** `correctIndex` وبدون `id` |
| `POST /api/exam/answer` | `{ examId, index, chosenIndex }` | `correctIndex` لهذا السؤال وحده، بعد التأكيد |
| `POST /api/exam/finish` | `{ examId }` | العلامة + مفتاح الإجابات كاملاً (لصفحة المراجعة) |

الخادم يحتفظ بالأسئلة المسحوبة وأجوبتها في الذاكرة (تُحذف بعد 3 ساعات)، ويحسب العلامة عنده،
فلا يستطيع المتصفّح تعديلها.

**ما الذي يحميه هذا فعلاً:** في تبويب Network لم تعد تظهر كل الأجوبة قبل الاختبار — بل جواب
واحد فقط بعد كل تأكيد. لكن ما يظهر على الشاشة يبقى موجوداً في المتصفّح بالضرورة؛ من يؤكّد
سؤالاً سيرى جوابه. الحماية هنا ضدّ قراءة المفتاح كاملاً مسبقاً، لا ضدّ الغش بالمطلق.

### الوضع الساكن — لا مكان تُخبَّأ فيه الأجوبة

> ⚠️ على GitHub Pages **لا يوجد خادم**، فملف مثل `questions.json` يُنزَّل كاملاً
> بحقول `correctIndex`. من يفتح تبويب Network أو يزور الرابط مباشرةً يرى مفتاح
> الإجابات كلّه. هذا ليس خللاً يمكن إصلاحه في الاستضافة الساكنة — إن كان إخفاء
> المفتاح شرطاً، فالنشر يجب أن يكون بصورة Docker على استضافة تشغّل Node.

ما يزال `exam-client.js` يفصل المفتاح عن واجهة العرض (`quiz.js` لا يستلم `correctIndex`
إلا بعد التأكيد)، لكن هذا ترتيب داخلي فقط ولا يمنع قراءة الملف مباشرةً.

> ⚠️ وبصرف النظر عن الاستضافة: إذا كان المستودع عاماً على GitHub فملفات الأسئلة
> مقروءة من صفحة المستودع نفسها.

## التنقّل بين الأسئلة

- زرّا **السابق / التالي** أسفل الشاشة للتنقّل بالترتيب.
- **شريط أرقام الأسئلة** أعلى السؤال: اضغط أي رقم للانتقال مباشرة إليه.
  - أخضر = أجبت صح، أحمر = أجبت خطأ، إطار متقطّع = اخترت إجابة ولم تؤكّدها بعد، أزرق = السؤال الحالي.
- يمكن تخطّي سؤال والرجوع إليه لاحقاً؛ الاختيار غير المؤكّد يبقى محفوظاً.
- السؤال المؤكَّد يبقى ظاهراً بإجابته الصحيحة عند الرجوع إليه ولا يمكن تغييره.
- في السؤال الأخير يتحوّل زر التالي إلى **إنهاء الاختبار**، مع تنبيه إذا بقيت أسئلة بدون إجابة.
- على الكمبيوتر: السهم ← للسؤال التالي، والسهم → للسؤال السابق.
- شريط التقدّم يعبّر عن **عدد الأسئلة المُجابة** من أصل 30.

## التشغيل محلياً

التطبيق يحتاج أن يُخدَم عبر `http://` — الفتح المباشر بالنقر المزدوج (`file://`) لن يعمل،
لأن المتصفّح يمنع `fetch` من الملفات المحلية:

```powershell
node serve.js
```

ثم افتح: `http://localhost:8777`

للاستماع على كل الشبكة (لتجربته من الهاتف مثلاً): `$env:HOST="0.0.0.0"; node serve.js`

لمعاينة نسخة GitHub Pages كما سيراها الزائر (بلا `/api`): `$env:YAM_STATIC="1"; node serve.js`

## الفحص الآلي (GitHub Actions)

كل `push` أو `pull request` على الفرع `main` يشغّل `.github/workflows/ci.yml`:

| الخطوة | ماذا تفحص |
|---|---|
| Syntax check | أن ملفات JavaScript تُقرأ بلا أخطاء صياغة |
| `scripts/validate.js` | كل ملفات الأسئلة + كل روابط الملفات المحلية |
| `scripts/smoke.js` | تشغيل `serve.js` فعلياً: كل صفحة + دورة اختبار كاملة عبر `/api` |
| `scripts/static-check.js` | مسار Pages: محتوى `_site` + دورة اختبار كاملة بلا خادم |

`validate.js` يرفض: JSON غير صالح، `id` مكرّر، `correctIndex` خارج نطاق `choices`،
خيار فارغ، سؤال بلا نص وبلا صورة، صورة غير موجودة، عدد أسئلة أقل من 30،
ورابطاً في HTML أو CSS يشير إلى ملف غير موجود.

و `smoke.js` يتحقق أيضاً من أن **بنوك الأسئلة ترجع 403** وأن الأسئلة المُرسَلة
لا تحمل `correctIndex` — أي أن حماية الأجوبة لم تنكسر بتعديل لاحق.

أمّا `static-check.js` فيشغّل `exam-client.js` نفسه داخل Node ويجري اختباراً كاملاً
بلا خادم: 30 سؤالاً، تصحيح صحيح، العلامة مطابقة، والجواب المؤكَّد لا يتغيّر. ويتحقق
أيضاً من أن `TAKE_COUNT` و `PASS_MARK` ما زالا متطابقين بين `serve.js` و `exam-client.js`،
ومن أن وجود الخادم **يمنع** السقوط إلى الوضع الساكن.

كما يتحقق `validate.js` من **حالة الأحرف** في أسماء الملفات: ويندوز لا يفرّق بين
`Logo.png` و `logo.png` لكن خادم لينكس يفرّق — فالخطأ يظهر هنا بدل أن يصبح 404 بعد النشر.

الفحص يعمل على Node **20** و **22** معاً.

لتشغيلها محلياً قبل الرفع:

```powershell
node scripts/validate.js
node scripts/smoke.js
```

## النشر

هناك طريقان، وكلاهما يعمل من نفس المستودع:

| | GitHub Pages | Docker |
|---|---|---|
| التكلفة | مجاني | يحتاج استضافة تشغّل Node |
| الإعداد | خطوة واحدة لمرّة واحدة | VPS أو Render / Railway / Fly.io |
| الأجوبة | تُنزَّل مع الأسئلة | تبقى على الخادم |

### GitHub Pages (النشر التلقائي)

**خطوة لمرّة واحدة:** في المستودع → **Settings** → **Pages** → تحت **Build and deployment**
اختر **Source: GitHub Actions**. لا تختر "Deploy from a branch".

بعدها كل `push` ناجح على `main` ينشر الموقع تلقائياً:

```
https://www.yamdrivingschool.com/
```

ما ينشره هو مجلّد `_site` الذي يبنيه `scripts/build-pages.js` — الصفحات والأسئلة
والصور و`exam-client.js` فقط. لا يُنشر `serve.js` ولا `Dockerfile` ولا `scripts/`.

لبناء المجلّد ومعاينته محلياً:

```powershell
node scripts/build-pages.js
$env:YAM_STATIC = "1"; node serve.js
```

`YAM_STATIC=1` يحاكي Pages: يعطّل `/api` ويسمح بتنزيل بنوك الأسئلة، فترى ما سيراه
الزائر تماماً. اقرأ التنبيه في [الوضع الساكن](#الوضع-الساكن--لا-مكان-تخبأ-فيه-الأجوبة)
قبل اعتماد هذا الطريق.

> المستودع الخاص يحتاج خطة **GitHub Pro** لتفعيل Pages. أمّا المستودع العام
> فملفات الأسئلة فيه مقروءة أصلاً من صفحة المستودع، فالنشر لا يضيف تسريباً جديداً.

### Docker — الأجوبة تبقى على الخادم

هذا هو الطريق الوحيد الذي يحافظ على `403` لبنوك الأسئلة.

#### الصورة (GitHub Container Registry)

عند نجاح الفحص على `main`، تبني الـ pipeline صورة من `Dockerfile`،
**تختبرها وهي تعمل** (الصفحة الرئيسية 200، بنوك الأسئلة 403، بدء اختبار بلا تسريب أجوبة)،
ثم تدفعها إلى GHCR بوسمين: `latest` و `sha-<commit>`.

```bash
docker pull ghcr.io/hasanf-01/yam-driving-school:latest
docker run -d -p 8777:8777 ghcr.io/hasanf-01/yam-driving-school:latest
```

> ⚠️ **GitHub يخزّن الصورة ولا يشغّلها.** لا توجد خدمة على GitHub تستضيف حاوية كموقع
> يستقبل زواراً. تحتاج مكاناً يشغّل الصورة: خادم VPS، أو Render / Railway / Fly.io
> موجَّهة إلى صورة GHCR نفسها.

الصورة تعمل بمستخدم غير جذر، وتقرأ `PORT` و `HOST` من البيئة، وفيها `HEALTHCHECK`.

### تنبيه مهم قبل التوسّع

جلسات الاختبار محفوظة **في ذاكرة العملية**: إعادة تشغيل الحاوية تُلغي الاختبارات
الجارية، وتشغيل أكثر من نسخة يتطلب تثبيت الجلسة على النسخة نفسها (sticky sessions)
وإلا فقد يصل طلب `‎/api/exam/answer‎` إلى نسخة لا تعرف الاختبار فترجع 404.

لاحظ أن جلسات الاختبار محفوظة **في ذاكرة العملية**: إعادة تشغيل الخادم تُلغي
الاختبارات الجارية، وتشغيل أكثر من نسخة يتطلب تثبيت الجلسة على النسخة نفسها.

## تعديل الأسئلة

كل ملف JSON عبارة عن مصفوفة بهذا الشكل:

```json
{
  "id": 1,
  "question": "نص السؤال",
  "image": "assets/signs/sign-000.png",
  "choices": ["الخيار الأول", "الخيار الثاني", "الخيار الثالث"],
  "correctIndex": 0
}
```

- `image` اختياري (احذفه أو اتركه فارغاً للأسئلة النصية).
- `correctIndex` يبدأ من **0**.
